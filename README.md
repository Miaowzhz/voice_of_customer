# 产品反馈 VOC 分析 Agent

通过飞书机器人提交一个产品的反馈数据，系统使用 LangGraph 编排大模型完成分析，并在飞书中返回简短结论、等级饼图和好评词云。

支持的输入格式：

- Excel、CSV、JSON 文件
- JSON 文本
- 飞书多维表格链接

测试数据：[data/product_feedback_demo.json](./data/product_feedback_demo.json)

## 主流程

```text
飞书机器人接收反馈
        ↓
读取 Excel / CSV / JSON / 多维表格
        ↓
清洗、去重、脱敏
        ↓
大模型逐条评价：好 / 中 / 差
        ↓
按等级分组
        ↓
分别分析好评原因、中评改进、差评原因
        ↓
汇总分析结果
        ↓
生成等级饼图和好评词云
        ↓
保存 SQLite 和本地报告
        ↓
返回飞书会话
```

批量反馈中的待复核记录不会阻塞整批分析，报告会标注待复核数量。

## 飞书交互方式

交互采用“立即确认、后台分析、随时查询”的方式。发送数据后机器人马上返回运行编号，分析在后台执行；同一聊天会记住最近一次运行，方便继续操作。

- `/状态`：查看最近一次运行状态
- `/报告`：重新发送最近一次摘要和图片
- `/状态 <run_id>`：查询指定运行
- `/报告 <run_id>`：查看指定运行报告
- `/新会话`：清除当前聊天关联的运行
- `/帮助`：查看使用说明

这套交互参考 Hermes Agent 的消息网关思路：平台接入只负责收消息，任务状态和分析流程由后台统一管理。

## 解决的主要痛点

### 1. 反馈入口分散

客户反馈来自客服、平台评论、Excel 和多维表格，格式不统一。项目用飞书机器人提供统一入口，自动读取并整理数据。

### 2. 人工分析效率低

人工逐条阅读、分类和判断好坏，耗时且标准不一致。系统使用大模型统一评价，并按好、中、差三个等级分析原因和改进方向。

### 3. 难以快速看出趋势

大量反馈很难直观看出整体体验。系统返回等级占比饼图和好评词云，帮助快速了解客户体验和产品优势。

### 4. 分析结果难以追溯

只在聊天中查看结果容易丢失。系统将原始反馈、分类结果、分析报告和图片保存到 SQLite 及本地目录，支持按运行编号查询。

## 快速启动

复制环境变量模板并填写飞书和 DeepSeek 配置：

```bash
cp .env.example .env
```

安装依赖并启动飞书长连接：

```bash
uv pip install --python .venv/bin/python -r requirements.txt
set -a
source .env
set +a
.venv/bin/python -m app.feishu_long_connection
```

启动后，在飞书中向机器人发送测试 JSON 文件，系统会先返回“正在分析”，完成后发送摘要、饼图和词云。

## 输出文件

每次运行会在 `artifacts/runs/<run_id>/` 下保存：

- `analysis.json`：结构化分析结果
- `analysis.md`：文字报告
- `grade_distribution.png`：好中差等级饼图
- `good_wordcloud.png`：好评词云

SQLite 数据库默认为项目根目录下的 `voc.db`。

详细实施设计见 [技术方案.md](./技术方案.md)。
